プラグインとは

feature-dev は Anthropic が公式に提供・検証した Claude Code 用プラグインで、 新機能開発を 7段階の構造化ワークフロー に沿って進める設計になっている。 単なるコード生成ツールではなく、「発見 → 探索 → 質問 → 設計 → 実装 → レビュー → サマリー」 というプロフェッショナルな開発プロセス全体を Claude Code 上で自動化する。


作者: Sid Bidasaria（Anthropic社員）— リポジトリ: anthropics/claude-plugins-official

設計思想

"Building features requires more than just writing code. You need to understand the codebase before making changes, ask questions to clarify ambiguous requirements, design thoughtfully before implementing, and review for quality after building."
🔍
理解してから変更する
既存コードを深く把握してから手を入れる。知らずに変えると壊す。
❓
曖昧さをゼロにする
実装前に全ての不明点を解消。あとで「こんなはずじゃなかった」を防ぐ。
🏗️
設計を先に行う
複数アプローチを比較検討してから実装。手戻りを最小化する。
🛡️
品質を組み込む
実装後に専門レビューエージェントが自動で問題を検出する。

7フェーズ ワークフロー

1
Phase 1
Discovery（発見）
何を作るかを明確化。問題の定義・制約条件の把握・理解の確認。
2
Phase 2
Codebase Exploration（探索）
code-explorer エージェントを 2〜3 個並列起動。類似機能・アーキテクチャ・読むべきファイルを洗い出す。
3
Phase 3
Clarifying Questions（質問）
エッジケース・エラーハンドリング・後方互換性など、残った曖昧さを全て解消。回答を待ってから次へ進む。
4
Phase 4
Architecture Design（設計）
code-architect が 3 つのアプローチ（最小変更・クリーン・バランス）を提案。推奨案付きで提示し、ユーザーが選択。
5
Phase 5
Implementation（実装）
明示的な承認を得てから実装開始。既存のコード規約に厳密に従いながら構築。
6
Phase 6
Quality Review（品質レビュー）
code-reviewer を 3 個並列起動。シンプルさ・バグ・規約の観点でレビュー。信頼度 80% 以上の問題のみ報告。
7
Phase 7
Summary（サマリー）
実装内容・主要決定・変更ファイル・次のステップをドキュメント化。

3つの専門エージェント

🔭
code-explorer

コードベース探索

実行パスを辿り、アーキテクチャの全体像をマッピング。類似実装・データフロー・依存関係を可視化する。Phase 2 で自動起動、手動呼び出しも可能。

エントリーポイント特定 データフロー追跡 依存関係マップ
🏛️
code-architect

アーキテクチャ設計

コードベースのパターンを分析し、複数の実装アプローチを設計。各アプローチのトレードオフを明示し、推奨案を提示する。

複数案提示 トレードオフ分析 実装ロードマップ
🔬
code-reviewer

コードレビュー

CLAUDE.md 準拠・バグ検出・コード品質の3観点で並列レビュー。信頼度 80% 以上の問題のみ報告し、ノイズを抑える。

バグ検出 規約チェック 信頼度フィルタリング

プラグインあり vs なしの比較

観点 ❌ プラグインなし（素の Claude Code） ✅ feature-dev あり
要件の扱い 指示されたまま実装を開始。曖昧さは実装中に表面化する Phase 1〜3 で全ての曖昧さを解消してから実装する
既存コードの理解 Claude の文脈理解に依存。大規模コードベースでは見落としやすい code-explorer が並列で実行パスを追い、既存パターンを確実に把握
設計判断 Claude が暗黙的に一つのアプローチを選択してしまうことが多い 3つのアプローチを比較提示し、ユーザーが意識的に選択できる
コードレビュー 別途依頼が必要。ユーザーが忘れると省略される Phase 6 で自動的に3エージェントによる多角的レビューが走る
並列エージェント活用 基本的にシングルスレッドで処理 探索・設計・レビューの各フェーズで 2〜3 エージェントを並列起動
コードベース整合性 既存パターンを無視した実装になる場合がある 探索フェーズで既存規約を学習し、それに従って実装
手戻りリスク 実装後に「要件が違う」「設計が合わない」が発覚しやすい 各フェーズの確認ポイントが手戻りを最小化する
適している場面 バグ修正・小規模変更・ワンショットのスクリプト作成 複数ファイルをまたぐ新機能・アーキテクチャ変更・要件が不明確な開発

使うべき場面 / 使わなくていい場面

✅ 使うべき
  • 複数ファイルをまたぐ新機能開発
  • アーキテクチャ上の判断が必要な実装
  • 既存コードとの複雑な統合
  • 要件が曖昧・不明確な機能
  • 品質と保守性が重要なコア機能
❌ 使わなくていい
  • 1行のバグ修正
  • 小規模で明確な変更
  • シンプルなスクリプト作成
  • 緊急のホットフィックス
  • 要件が完全に定義済みのタスク

インストールと使い方

インストール

Claude Code 内で以下を実行：

/plugin install @claude-plugins-official/feature-dev

基本的な使い方

インストール後、Claude Code 内で：

/feature-dev Add user authentication with OAuth

7フェーズのインタラクティブなワークフローが起動する。各フェーズで確認ポイントがあり、ユーザーの判断を経てから次へ進む。

エージェントの手動呼び出し

フルワークフロー以外にも、個別エージェントを直接呼び出せる：

"Launch code-explorer to trace how authentication works"
"Launch code-architect to design the caching layer"
"Launch code-reviewer to check my recent changes"

まとめ

feature-dev プラグインの本質は、「急いでコードを書くより、理解してから書いた方が速い」 という逆説的な設計思想にある。 並列エージェントによる探索・複数アーキテクチャ案の提示・自動コードレビューを組み合わせることで、 個人開発でもチーム開発のベストプラクティスに近い品質を担保できる。


13万以上のインストール数が示す通り、「Claude Code に言えばなんとかしてくれる」ではなく 「Claude Code と一緒に正しく開発する」というアプローチへの需要が高い。 特に大規模コードベースや要件が曖昧なプロジェクトでは、フルワークフローの価値が高い。
