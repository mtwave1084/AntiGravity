エグゼクティブサマリー

一言で言うと：AIエージェントが各サービスを読めない・検索できない・設定が散らばるという悩みを、まとめて片づける「工具箱」。ラッパーやフレームワークではなく、上流ツールを揃えて管理する scaffolding。インストール後、エージェントは上流ツールを直接呼ぶ。

何ができるか

Web読取・YouTube字幕・GitHub・Twitter/X・RSS・Reddit・中国系SNSなど14+チャネルの「読む・探す・監視する」をカバー。

どう実現しているか

Jina Reader・yt-dlp・bird（X用CLI）・gh CLI・feedparser・mcporter 等の上流ツールをまとめてインストール・設定。Agent-Reach 自体は呼ばれない。

MCP統合の実態

MCP サーバーは存在するが、公開ツールは get_status（doctor 状態確認）のみ。read/search は MCP ツール未実装。Bash 経由で上流ツールを直接呼ぶ運用になる。

設計思想

CLAUDE.md より（開発者コメント）

"Positioning: installer + doctor + config tool. NOT a wrapper — after install, agents call upstream tools directly."

チャネル契約（base.py）

全チャネルは BaseChannel を継承し can_handle(url) / read(url) / search(query) / check() を実装する。独立・可換な設計。

安全性

MIT ライセンス・全オープンソース監査可能。認証情報は ~/.agent-reach/config.yaml（パーミッション600）にローカル保存。safe フラグ・dry-run サポート。

優先度 チャネル 活用シーン 備考
高 Twitter / X @superecochan など参照アカウント調査、AIニュース速報確認 専用小アカのCookie要。本アカ不可
高 YouTube AIニュース動画の字幕取得・内容確認 Cookie不要で使いやすい

中 GitHub OSSリポジトリ・Issue・PRの調査 gh CLI 既存のため優先度低め
低 中国系チャネル 現時点では不要 設定が複雑・当面スキップ推奨

推奨導入フロー（段階的）

1

Web / YouTube / RSS / GitHub 公開情報

Cookie不要・安全圏。まずここから始めると詰まりにくい。Claude Code の調査力を即座に底上げできる。

2

X / Twitter

専用小アカのCookieを Cookie-Editor でエクスポートしてから導入。Gemini 503 時の X調査補完として機能。

3

agy 定型フローへの統合

ai-news の YouTube動画字幕確認 / X 投稿調査 / RSS 定点ウォッチなどを組み込む。

注意点

運用上の注意 重要

  • Cookieチャネル（X/XHS）は本アカ不使用。専用小アカを用意する
  • サーバー環境では Reddit / Bilibili がプロキシ必要になる場合あり
  • 共有環境では --safe / --dry-run で事前確認
  • 外部依存多いので定期的に doctor コマンドで状態確認

設計上の注意 把握

  • MCP サーバーは status 確認のみ。read/search は Bash 経由
  • 上流ツール（bird / yt-dlp 等）の仕様変更に注意
  • guides / README は頻繁に更新される。古いメモより公式最新を優先
  • 問いの質がそのまま収集品質に反映される
Copilot レポートの評言を引用：「AIがツール地獄へ代わりに入ってくれる道具」。夢の杖というより、よく整った工具箱。
