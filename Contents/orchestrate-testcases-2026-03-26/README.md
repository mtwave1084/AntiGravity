# AIオーケストレーション テストケース集

作成日: 2026-03-26  
対象スキル: `.claude/skills/orchestrate/SKILL.md`

## この資料の目的

Claude Code を司令塔として、`Codex CLI` と `Gemini CLI` を適切に振り分ける練習をするためのテストケース集。  
単なる正答確認ではなく、以下を引き出すことを重視している。

- どのAIに何を任せるべきかの判断
- 途中で詰まった理由の言語化
- リサーチ不足、分解不足、検証不足の特定
- スキル本文やルーティング規則の改善点の洗い出し

## 使い方

1. 各例題をそのままオーケストレーション入力として使う
2. 実行後に「どこで迷ったか」「どのAIへの依頼文が弱かったか」を振り返る
3. `期待する役割分担` と実際の分担がズレた理由を確認する
4. `振り返り観点` をもとにスキル改善案をメモする

## 分類方針

5種類のタスクタイプを用意し、それぞれ5問ずつ作成した。

- 調査・比較型
- 設計・方針決定型
- 実装・自動化型
- レビュー・改善提案型
- コンテンツ制作型

## 1. 調査・比較型

### Case 1-1 競合サービス比較から訴求軸を決める

**例題**

「AIエージェント学習講座の訴求軸を決めたい。」  
「具体的には主要な競合講座を5つ調べて、価格帯・対象者・約束している成果を比較し、最後にうちが勝ちやすい切り口を3案に絞る流れでお願い。」

**狙い**

- Gemini に競合調査を振る判断ができるか
- Claude が比較観点を整理し、意思決定まで持っていけるか

**期待する役割分担**

- Gemini: 競合調査、比較表の素案、差分の抽出
- Claude: 比較観点の統一、訴求軸の優先順位付け、最終要約

**振り返り観点**

- 競合の選定根拠は明確だったか
- 比較項目が揃っていたか
- 「調べた」で終わらず意思決定まで進めたか

### Case 1-2 YouTubeテーマの需要検証をする

**例題**

「AI副業チャンネルの次の企画テーマを決めたい。」  
「具体的には候補テーマを6つ並べて、それぞれの検索需要や話題性を調べ、競争が激しすぎない順に優先度を付ける流れでお願い。」

**狙い**

- 調査結果を企画優先度に変換できるか
- 需要だけでなく競争密度も見る設計ができるか

**期待する役割分担**

- Gemini: 話題性、検索ニーズ、類似動画傾向の調査
- Claude: 優先度ロジックの策定、企画会議向け結論化

**振り返り観点**

- 判断軸が曖昧なまま順位付けしていないか
- 一次情報と推測が混ざっていないか
- 調査範囲が広すぎて結論がぼけていないか

### Case 1-3 新しい販売チャネルの候補を探す

**例題**

「既存のBrain以外でデジタル商品を売る販路を広げたい。」  
「具体的には国内向けで相性の良さそうな販売チャネルを5つ調べて、手数料・集客のしやすさ・AI系コンテンツとの相性を比較し、試す順番まで出す流れでお願い。」

**狙い**

- 調査から実行順まで落とし込めるか
- チャネル比較で運用負荷も見られるか

**期待する役割分担**

- Gemini: サービス候補調査、料金体系や特徴の整理
- Claude: 評価基準の統一、試行順序の決定

**振り返り観点**

- 「相性」の定義が曖昧ではなかったか
- 販売者視点の実務条件まで見ていたか
- すぐ試せる案と中長期案が分けられていたか

### Case 1-4 法改正や規約変更の影響を把握する

**例題**

「AI生成コンテンツ販売まわりで最近の規約変更がないか確認したい。」  
「具体的には主要プラットフォームをいくつか調べて、禁止事項や要注意表現の変更点を整理し、今の販売ページで見直すべき箇所を洗い出す流れでお願い。」

**狙い**

- 高リスクな調査を Gemini に振りつつ、Claude が慎重に要約できるか
- 調査結果を実務上の修正項目に変換できるか

**期待する役割分担**

- Gemini: 最新規約の調査と変更点の抽出
- Claude: リスクレベルの整理、対応タスク化

**振り返り観点**

- 出典が曖昧な情報を混ぜていないか
- 変更点と推奨解釈を区別しているか
- 実務に必要な次アクションに変換できたか

### Case 1-5 海外事例から新企画のヒントを拾う

**例題**

「海外のAIエージェント運用事例から商品アイデアを見つけたい。」  
「具体的には海外の事例をいくつか調べて、どんな課題をどう解決しているかをまとめ、うちの顧客向けに転用できそうな企画を4案出す流れでお願い。」

**狙い**

- 広いリサーチを企画転用まで進められるか
- Gemini の探索力を Claude が収束させられるか

**期待する役割分担**

- Gemini: 海外事例の発掘、論点整理
- Claude: 国内向けに翻訳、商品アイデア化

**振り返り観点**

- 事例収集だけで終わっていないか
- 国内顧客に合わせた変換ができているか
- アイデアの重複や粒度のブレはないか

## 2. 設計・方針決定型

### Case 2-1 新サービスのオンボーディング設計

**例題**

「初心者向けAI講座の初回オンボーディング体験を設計したい。」  
「具体的には受講開始から最初の30分で何をさせるべきかを整理して、離脱しにくい順番に並べ、最後に画面遷移レベルのフローにする流れでお願い。」

**狙い**

- Claude が設計の主担当になれるか
- 必要に応じて Gemini に参考事例調査を振れるか

**期待する役割分担**

- Gemini: 類似サービスの初期体験調査
- Claude: 情報設計、順序設計、離脱要因の抑制

**振り返り観点**

- ユーザー心理の変化を踏まえた構成か
- 手順が多すぎていないか
- 「何を捨てるか」まで決められたか

### Case 2-2 エージェント運用ルールの設計

**例題**

「チーム内でAIエージェントを安全に運用するルールを決めたい。」  
「具体的にはリサーチ、実装、レビュー、公開前確認の各場面で誰が何を承認するべきかを整理して、運用ルールの草案にまとめる流れでお願い。」

**狙い**

- Claude がポリシー設計を主導できるか
- Codex を使うべき場面と使わない場面を切り分けられるか

**期待する役割分担**

- Claude: 役割分担、承認ルール、例外条件の設計
- Gemini: 他社・一般論の参考観点調査

**振り返り観点**

- ルールが抽象的すぎないか
- 実運用で詰まりそうな分岐を拾えているか
- 安全性とスピードのバランスは取れているか

### Case 2-3 新機能の優先順位を決める

**例題**

「AIコンテンツ制作ツールの次の開発優先順位を決めたい。」  
「具体的には候補機能を7つ並べて、実装コスト・売上インパクト・差別化の観点で評価し、今月やるものと後回しにするものを分ける流れでお願い。」

**狙い**

- Claude が意思決定フレームを作れるか
- Codex を使って実装難易度の当たりを取らせる発想が出るか

**期待する役割分担**

- Codex: 既存コードから実装難易度の当たりを確認
- Claude: 優先順位付け、ロードマップ化

**振り返り観点**

- 技術負債や依存関係を見落としていないか
- 売上インパクトが主観だけになっていないか
- 「やらない理由」が説明できているか

### Case 2-4 コンテンツ量産フローの再設計

**例題**

「メルマガ、X、動画台本を一気通貫で量産する制作フローを組み直したい。」  
「具体的にはアイデア出しから配信予約までの工程を整理して、どこを人間が見てどこをAIに任せるかを決め、ボトルネックを減らす流れでお願い。」

**狙い**

- Claude が業務設計に強く出られるか
- Gemini でアイデア源、Codex で自動化候補を補助できるか

**期待する役割分担**

- Gemini: 量産フローの他社事例や発想支援
- Codex: 自動化可能な工程の洗い出し
- Claude: 全体フロー設計、役割分担の最終化

**振り返り観点**

- 人の判断が必要な場所を残せているか
- 自動化候補が具体的か
- フローが長くなりすぎていないか

### Case 2-5 KPIダッシュボードの設計

**例題**

「AI講座販売の状況を毎週見直せるKPIダッシュボードを設計したい。」  
「具体的には見るべき数字を洗い出して、売上だけでなく集客、教育、継続率まで含めて構造化し、毎週の確認順まで決める流れでお願い。」

**狙い**

- 指標設計を抽象論で終わらせず運用手順にできるか
- Claude が情報構造をまとめられるか

**期待する役割分担**

- Claude: KPI階層の設計、レビュー順の提案
- Gemini: 業界ベンチマークや参考指標の調査

**振り返り観点**

- 指標が多すぎないか
- 行動につながる指標になっているか
- 毎週見られる粒度に収まっているか

## 3. 実装・自動化型

### Case 3-1 競合記事の要約パイプラインを作る

**例題**

「競合のAIニュース記事を毎日まとめる半自動フローを作りたい。」  
「具体的には記事URLをまとめて入れたら要約候補が並ぶ仕組みを考えて、必要ならスクリプトも触りつつ、最後に運用手順まで整理する流れでお願い。」

**狙い**

- Codex に実装やスクリプト確認を振れるか
- Gemini を情報収集役として併用できるか

**期待する役割分担**

- Gemini: 記事収集観点や入力候補の整理
- Codex: スクリプトやワークフローの実装確認
- Claude: 全体の接続と運用手順化

**振り返り観点**

- 実装対象と運用説明が分離できているか
- 例外ケースを考慮できているか
- 自動化範囲が過剰になっていないか

### Case 3-2 既存スクリプトの安全化

**例題**

「既存のバッチ処理を安全に回せるようにしたい。」  
「具体的には現在のスクリプトを確認して、危険な処理やログ不足を洗い出し、必要なら修正案まで出して、最後に安全運用チェックリストを付ける流れでお願い。」

**狙い**

- Codex でコード確認、Claude で運用整理ができるか
- レビューと修正案の両方にまたがるタスクを扱えるか

**期待する役割分担**

- Codex: スクリプト読解、危険箇所の指摘、修正案
- Claude: 安全運用チェックリスト化

**振り返り観点**

- 指摘が抽象的になっていないか
- 実行リスクの優先順位が付いているか
- 修正後の確認方法まで含められたか

### Case 3-3 テンプレートから量産用ページを生成する

**例題**

「講座紹介ページをテンプレートから量産できる状態にしたい。」  
「具体的には必要な入力項目を整理して、HTMLの差し替えや生成の流れを決め、最小構成の実装方針までまとめる流れでお願い。」

**狙い**

- 設計と実装の境界をまたぐ依頼を捌けるか
- Codex がテンプレート化の技術論点を拾えるか

**期待する役割分担**

- Codex: テンプレート化の技術確認、実装叩き台
- Claude: 必要入力の設計、運用フローの決定

**振り返り観点**

- 入力項目が不足していないか
- 実装方針が過大でないか
- 運用者が迷わない形になっているか

### Case 3-4 レポート出力を自動整形する

**例題**

「AIの実行結果を毎回見やすいHTMLレポートに整形したい。」  
「具体的には既存の出力形式を確認して、共通テンプレートを作る方針を決め、必要なら変換スクリプト案まで出す流れでお願い。」

**狙い**

- Codex に変換ロジックを振り、Claude が見せ方を決められるか
- スタイル設計と実装設計を分担できるか

**期待する役割分担**

- Codex: 変換スクリプトやテンプレート構造の確認
- Claude: レポートの情報設計と表示優先順位

**振り返り観点**

- 可読性と実装コストのバランスは取れているか
- 入力フォーマットの揺れを想定できているか
- 再利用性のある設計になっているか

### Case 3-5 定期タスクの失敗検知を入れる

**例題**

「定期実行しているAIタスクが失敗した時にすぐ気づけるようにしたい。」  
「具体的には現在の定期処理を確認して、失敗パターンを洗い出し、通知や再実行の仕組みを最小構成で提案する流れでお願い。」

**狙い**

- Codex に現状確認をさせつつ、Claude が運用設計までまとめられるか
- 障害対応の観点をテストできるか

**期待する役割分担**

- Codex: 定期処理、ログ、失敗条件の把握
- Claude: 通知方針、再実行ルール、優先対応案

**振り返り観点**

- 失敗定義が曖昧ではないか
- 通知過多にならない設計か
- 最低限の運用で回せる提案になっているか

## 4. レビュー・改善提案型

### Case 4-1 スキルの弱点レビュー

**例題**

「オーケストレーション用スキルの弱点を洗い出したい。」  
「具体的には今のスキル定義を読んで、曖昧な指示、抜けている分岐、誤ルーティングしやすい箇所を指摘し、改善案を優先度付きで出す流れでお願い。」

**狙い**

- Claude にレビュー主導をさせられるか
- Codex を読解補助に回すかどうかの判断を見たい

**期待する役割分担**

- Codex: スキル文面の構造把握、曖昧箇所の抽出補助
- Claude: 問題の優先順位付け、改善案の統合

**振り返り観点**

- 指摘が具体的か
- 改善案が運用に落ちるか
- 重大度の差が整理されているか

### Case 4-2 既存HTMLレポートの品質レビュー

**例題**

「過去に作ったHTMLレポートの品質を見直したい。」  
「具体的には読みやすさ、構造、情報量、再利用しやすさの観点でレビューして、直すならどこから直すべきか順位を付ける流れでお願い。」

**狙い**

- デザインレビューと構造レビューを分けて考えられるか
- Codex に実装観点の問題を拾わせられるか

**期待する役割分担**

- Codex: HTML/CSS構造、保守性、再利用性の観点で確認
- Claude: 読者価値、情報設計、改善優先度の決定

**振り返り観点**

- 好みと問題点を混同していないか
- 直す理由が説明できているか
- 改善の順番が妥当か

### Case 4-3 自動生成コンテンツの品質レビュー

**例題**

「AIが作ったブログ下書きの品質を安定させたい。」  
「具体的には過去の下書きを数本見て、構成の癖や弱い表現を洗い出し、再現しやすい改善ルールに変換する流れでお願い。」

**狙い**

- Claude に文章レビューを任せつつ、Codex をルール化補助に使えるか
- 品質改善を再現可能なルールに落とせるか

**期待する役割分担**

- Claude: 文章品質レビュー、改善ルールの抽象化
- Codex: ルールファイル化やテンプレ化の観点補助

**振り返り観点**

- 感想ではなくルールに変換できているか
- 再現可能な粒度になっているか
- 例外条件まで触れられているか

### Case 4-4 運用ログから詰まりどころを分析する

**例題**

「AI活用フローのどこで毎回時間を使っているのか知りたい。」  
「具体的には最近の作業ログやメモを見て、詰まりやすい工程を分類し、AIへの依頼文や手順のどこを直すと改善するか提案する流れでお願い。」

**狙い**

- 振り返りログを改善提案に変換できるか
- Claude が業務改善目線を持てるか

**期待する役割分担**

- Claude: ログ分析、ボトルネックの分類、改善策立案
- Codex: ログの形式整理や集計補助が必要なら担当

**振り返り観点**

- 原因と症状を分けて考えられているか
- 改善提案が実行可能か
- ログ不足自体を課題として拾えているか

### Case 4-5 指示文テンプレートの改善

**例題**

「AIに渡す依頼文の品質を上げたい。」  
「具体的には最近よく使っている依頼文をいくつか見て、曖昧な書き方や不足情報を洗い出し、用途別に使い回せるテンプレートへ改善する流れでお願い。」

**狙い**

- スキル改善の上流にある依頼品質も見直せるか
- Claude がテンプレート設計をできるか

**期待する役割分担**

- Claude: 依頼文レビュー、テンプレート化
- Gemini: 必要なら良いプロンプト構成の参考観点調査

**振り返り観点**

- 何が不足していたかが明確か
- 用途ごとの差分が整理されているか
- テンプレートが長すぎないか

## 5. コンテンツ制作型

### Case 5-1 リサーチ付き動画台本を作る

**例題**

「AIエージェント入門動画の台本を作りたい。」  
「具体的には最近の事例を軽く調べてから、初心者がつまずくポイントを先回りして説明する構成を作り、最後に5分動画の台本に落とす流れでお願い。」

**狙い**

- Gemini のリサーチと Claude の構成力を連携できるか
- 事実確認と台本化の切り替えができるか

**期待する役割分担**

- Gemini: 最近の事例や話題の調査
- Claude: 構成設計、台本作成、わかりやすさの担保

**振り返り観点**

- リサーチ内容が台本に活きているか
- 初心者向けの難易度調整ができているか
- 話が広がりすぎていないか

### Case 5-2 セールス記事の骨子を作る

**例題**

「AIオーケストレーション講座の販売記事の骨子を作りたい。」  
「具体的には想定読者の悩みを整理して、競合との差別化も踏まえた章立てを作り、各章で何を言うか一行ずつ要約する流れでお願い。」

**狙い**

- 調査、設計、コピーの3要素をつなげられるか
