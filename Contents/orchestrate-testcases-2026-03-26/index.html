Orchestrate Skill Testbook

AIオーケストレーション テストケース集

`.claude/skills/orchestrate/SKILL.md` を実戦投入するための例題を、5分類 x 5問の計25問で整理した。狙いは、正答ではなく、どのAIに何を振るべきか、どこで詰まるか、スキル文面に何が足りないかを露出させることにある。

作成日: 2026-03-26 対象: Claude Code / Codex CLI / Gemini CLI 用途: 実行テスト / 振り返り / スキル改善

設計方針

調査、設計、実装、レビュー、コンテンツ化の5系統で分類。

分類の意図

オーケストレーションで迷いやすいのは、調査寄りか、実装寄りか、意思決定寄りかが曖昧な時。分類を固定して、誤ルーティングの癖を見つけやすくした。

観察したいこと

どのAIに何を任せたかだけでなく、途中で依頼文をどう修正したか、どの時点で確認を入れるべきだったかも記録対象にする。

振り返りの焦点

「分解不足」「調査不足」「検証不足」「依頼文不足」のどれが原因かを見分ける。スキル改善の入口は失敗のラベル付けにある。

1. 調査・比較型

Gemini で広く集め、Claude で比較と意思決定へ収束。

Case 1-1

競合サービス比較から訴求軸を決める

例題

「AIエージェント学習講座の訴求軸を決めたい。」

「具体的には主要な競合講座を5つ調べて、価格帯・対象者・約束している成果を比較し、最後にうちが勝ちやすい切り口を3案に絞る流れでお願い。」

狙い

調査を比較表にし、そのまま訴求案へ変換できるかを見る。

期待する役割分担

Gemini: 競合調査Claude: 比較軸整理と意思決定

振り返り観点

  • 競合選定の根拠があるか
  • 比較軸が揃っているか
  • 調査止まりで終わっていないか
Case 1-2

YouTubeテーマの需要検証をする

例題

「AI副業チャンネルの次の企画テーマを決めたい。」

「具体的には候補テーマを6つ並べて、それぞれの検索需要や話題性を調べ、競争が激しすぎない順に優先度を付ける流れでお願い。」

狙い

需要と競争密度を両方見た順位付けができるかを見る。

期待する役割分担

Gemini: 話題性と需要調査Claude: 優先度ロジックと結論化

振り返り観点

  • 判断軸が明文化されているか
  • 推測と事実が分離されているか
  • 範囲を広げすぎていないか
Case 1-3

例題

「既存のBrain以外でデジタル商品を売る販路を広げたい。」

「具体的には国内向けで相性の良さそうな販売チャネルを5つ調べて、手数料・集客のしやすさ・AI系コンテンツとの相性を比較し、試す順番まで出す流れでお願い。」

  • 相性の定義があるか

  • 短期案と中長期案が分かれているか
Case 1-4

法改正や規約変更の影響を把握する

例題

「AI生成コンテンツ販売まわりで最近の規約変更がないか確認したい。」

「具体的には主要プラットフォームをいくつか調べて、禁止事項や要注意表現の変更点を整理し、今の販売ページで見直すべき箇所を洗い出す流れでお願い。」

狙い

期待する役割分担

  • 出典の確からしさは十分か
  • 変更点と解釈を分けたか
  • 次アクションまで出せたか
Case 1-5

海外事例から新企画のヒントを拾う

例題

「海外のAIエージェント運用事例から商品アイデアを見つけたい。」

「具体的には海外の事例をいくつか調べて、どんな課題をどう解決しているかをまとめ、うちの顧客向けに転用できそうな企画を4案出す流れでお願い。」

狙い

スキル改善の観点

この25問を回した後は、成功率よりも「迷い方」を見る。特に以下が頻出するなら、スキルの改善余地が大きい。

  • レビュー系と方針決定系のルーティング規則が弱い
  • 途中停止条件や確認ポイントが明文化されていない
  • `.ai-consults/` のログをどう評価するか決まっていない
  • 実行後の自己評価テンプレートがなく、学習が蓄積しない
  • 依頼文テンプレートの不足が、誤ルーティングの原因になっている
