2026-03-24 時点

Claude Code を司令塔にして、Codex CLI / Gemini CLI を適材適所で相談相手にする設計

結論: 司令塔は Claude Code、実行・検証係は Codex CLI、調査・要約係は Gemini CLI がもっとも現実的です。Claude Code は hooks / skills / subagents / agent teams / worktree / MCP を持ち、オーケストレーションの材料が最も豊富です。Codex CLI は sandbox / approvals / non-interactive が強く、Gemini CLI は web search / web fetch / hooks / custom commands / GEMINI.md が強い、という住み分けです。[S1][S2][S3][S4][S5][S7][S9][S10][S11][S12]

Claude Code = 親分Codex CLI = 安全実行・CIGemini CLI = 調査・比較・長文要約

1. サマリー

Claude Code

A+ 司令塔向き

  • hooks / skills / subagents / agent teams / worktree が揃う。[S1][S2][S3][S4]
  • コミュニティでも「CLI 体験が最良」「エージェントとして完成度が高い」という評判。[C1][C2][C3]

Codex CLI

A 実行・検証向き

  • OS レベル sandbox、approval、codex exec が強い。[S5][S7][S8]
  • JSONL 出力で他エージェントから取り込みやすい。[S7][S8]
  • ユーザー評価では「賢いがやや遅い」「ピンポイント修正に強い」。[C1][C2][C4]

Gemini CLI

A- 調査・要約向き

  • web search / fetch / hooks / custom commands / GEMINI.md が強い。[S9][S10][S11][S12]
  • 無料〜低コストで触りやすいという評価が多い。[S9][C2][C4]
  • 巨大文脈や検索は魅力だが、複雑実装の完成度は Claude/Codex 優勢という声。[C1][C2][C3]

3. 推奨ロール分担

Claude Code の役割

  • 依頼の解釈とタスク分解
  • リポジトリ全体の把握
  • 誰に投げるかの判断
  • 最終統合と差分整合

Codex CLI の役割

  • テスト実行・ログ解析・再現検証
  • CI / バッチ / 自動レビュー
  • 安全制御が重要な shell 実行
  • 機械可読な結果出力

Gemini CLI の役割

  • 仕様調査・比較・周辺情報収集
  • 長文・大量ファイルの俯瞰
  • Web 検索前提の要件整理
  • ドラフト要約

4. 実装方法（最初にやるべき形）

おすすめは、Claude Code の custom command / skill から Bash で Codex CLI / Gemini CLI を呼ぶ方法です。MCP で大掛かりに組む前に、まずは wrapper script 方式のほうが壊れにくく、差し替えやすいです。Claude は skills / custom commands を持ち、Codex は codex exec、Gemini は hooks / custom commands / GEMINI.md を持つので、この接着剤設計がしやすいです。[S3][S7][S11][S12]

# 1) 3つの指示ファイルを揃える
CLAUDE.md   # Claude Code 用
AGENTS.md   # Codex CLI 用
GEMINI.md   # Gemini CLI 用

# 中身は極力共通化
- 変更前に関連ファイルを読む
- TypeScript は strict 維持
- 変更後は lint/test を実行
- 危険コマンドは承認必須
- 出力順は「結論→根拠→残課題」
#!/usr/bin/env bash
# scripts/consult-codex.sh
set -euo pipefail
mkdir -p .ai-consults
OUT=".ai-consults/codex-$(date +%Y%m%d-%H%M%S).md"
codex exec --sandbox read-only --ask-for-approval never   "あなたはコード検証専門。観測→原因→修正案→再確認項目で答える。 $*" > "$OUT"
echo "$OUT"
#!/usr/bin/env bash
# scripts/consult-gemini.sh
set -euo pipefail
mkdir -p .ai-consults
OUT=".ai-consults/gemini-$(date +%Y%m%d-%H%M%S).md"
# 記法差があり得るため実運用前に gemini --help を確認
gemini -p "あなたは調査専門。結論→根拠→参考URL→不確実点で要約。 $*" > "$OUT"
echo "$OUT"
# .claude/commands/route-task.md の例
あなたは司令塔。
- コード修正の再現検証 / テスト実行 / CI 寄り -> Codex CLI
- Web 調査 / 長文要約 / 周辺技術比較 -> Gemini CLI
- 複数ファイル横断の設計変更 / 最終統合 -> Claude Code が主担当

手順:
1. 依頼を要約
2. 振り分け理由を3点で示す
3. 必要なら scripts/consult-codex.sh または scripts/consult-gemini.sh を Bash で実行
4. 返りファイルを読んで最終統合する

Hook は最初から自動委譲に使わず、「この依頼は Codex / Gemini に向く」と提案する程度から始めるのが安全です。Claude Code と Gemini CLI はどちらも hooks を持ちますが、完全自動化は無限ループと二重実行の温床になりがちです。[S2][S11]

5. 最終提案

  • 採用推奨: Claude Code = 司令塔、Codex CLI = 実装検証係、Gemini CLI = 調査要約係
  • 最初の一歩: 3つの記憶ファイルを揃える → wrapper script を作る → /route-task を作る
  • 運用方針: まずは明示コマンド中心、うまく回ってから hooks で半自動化

要するに、Claude Code を「考えて振る親分」にして、Codex と Gemini は「専門店」として使うのが、いちばん実務的で壊れにくいです。
