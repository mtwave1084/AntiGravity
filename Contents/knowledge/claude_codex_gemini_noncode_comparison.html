Claude Code / Codex CLI / Gemini CLI 比較
— CLI操作・クリエイティブ制作・ゲーム企画/設計 編 —

前回の「コーディング中心の比較」と同じ切り口で、今回は ① CLIによる環境構築やPC操作、② クリエイティブ制作（作曲の企画、動画企画、構成づくり）、③ ゲーム企画から設計 に広げて比較した版です。
結論だけ先に言うと、司令塔はやはり Claude Code、CLIで安全に動かす実行係は Codex CLI、リサーチとネタ出し・構成化は Gemini CLI がいちばん自然です。

※ 作業適性は公式が断言しているわけではないため、公式機能とコミュニティの使用感を分けて評価しています。

1. 先に結論

Claude Code

全体司令塔に最適

総合 A+

  • hooks / skills / subagents / agent teams / worktree / Chrome連携があるので、「考えて振る」役がしやすい。
  • 特に複数の作業を並行で回す設計、長いタスクの構造化、最終統合が得意。
  • コミュニティでも「CLI体験が最も完成されている」「一般アシスタント寄りの使い方でも扱いやすい」という声がある。
Codex CLI

安全実行・検証担当に最適

総合 A

  • OSレベル sandbox、approval、codex exec、JSONL 出力が強い。
  • 「環境構築」「CLI操作」「バッチ」「再現テスト」「ログ解析」みたいな、失敗コストの高い実行仕事に向く。
  • スクリーンショットや設計画像も扱えるので、UI仕様の実装や差分確認にも相性がよい。
Gemini CLI

リサーチ・アイデア展開に最適

総合 A-

  • Web search / fetch、deep research 系の思想、GEMINI.md、hooks / custom commandsが強い。
  • 公式でも content generation / deep research / task management を打ち出している。
  • 「企画の叩き台」「比較調査」「競合分析」「大量情報の要約」ではかなり頼れる。

2. ドメイン別の比較

2-1. CLIによる環境構築やPCの操作

ツール評価向いていることひとこと
Codex CLI A+ 環境構築、パッケージ導入、再現テスト、ログ解析、CIバッチ、機械可読な結果収集 いわば「安全靴を履いた作業員」。read-only / workspace-write / danger-full-access と approval が明確なので、PC操作を任せるなら最有力。
Claude Code A 複数ステップの手順化、ブラウザ操作込みのE2E、環境構築の全体設計、分担管理 Chrome連携でページ操作・フォーム入力・データ抽出までできるので、「端末 + ブラウザ」の横断作業は強い。ただし安全面は Codex より運用設計に依る。
Gemini CLI B+ 手順の下調べ、外部情報の確認、シェルを使った補助作業、ドキュメント整理 環境構築そのものもできるが、真価は「調べながら進める」こと。PC操作の主役というより、横で資料を集める参謀。

推奨: Claude Code が手順を分解 → Codex CLI が安全に実行 → Gemini CLI が不足情報を調査 の流れ。

2-2. クリエイティブの作成（作曲の企画、動画企画、構成・台本づくり）

ツール評価向いていることひとこと
Gemini CLI A 企画の幅出し、競合比較、トレンド整理、長文要約、インプットの構造化、媒体別の案出し 公式でもcontent generation と deep research / task management を前面に出しており、動画企画・記事構成・世界観リサーチの叩き台づくりがうまい。
Claude Code A- 企画を一つの筋にまとめる、長い制作工程の分解、複数案の比較、実制作タスクへの落とし込み 「ネタをばらまく」より、「一本の企画に仕立てる」のが得意。クリエイティブのPMっぽい役回り。
Codex CLI B 画像・モック・図からの実装寄り整理、プロトタイプ、補助スクリプト、資料整形 コード化・構造化は強いが、発想を広げるタイプではない。創作の本丸より、試作と検証の職人。

推奨: Gemini CLI で素材を集めて案を広げる → Claude Code で企画として束ねる → Codex CLI で補助ツールや試作を作る の流れ。

2-3. ゲームの企画から設計

ツール評価向いていることひとこと
Claude Code A ゲーム企画書の構成、ルール設計、状態遷移、サブシステム分解、仕様書の統合 複数の要素（世界観 / ループ / 戦闘 / UI / 進行）をつないで、一貫した設計書にする役として優秀。
Gemini CLI A- 競合ゲームの調査、用語集や世界観資料の比較、遊びの幅出し、参考事例の収集 「何を参考にするか」「どこを差別化するか」を探す段階で強い。企画前半の探索機。
Codex CLI B+ UIモックからの実装、ゲームループの試作、プロトタイプコード、ツールづくり ゲームデザインそのものより、設計を動く試作に変える役で光る。

推奨: Gemini CLI で調査 → Claude Code でゲームデザイン文書化 → Codex CLI で試作 がきれい。

3. なぜそう判断したか（機能面）

Claude Code の強み

  • CLI / IDE / Desktop / Web で使える。
  • skills / hooks / subagents / agent teams により、役割分担と自動化の材料が豊富。
  • Chrome 連携で、Webアプリのテスト、フォーム入力、データ抽出、ログイン済みサイト操作まで可能。
  • 「1つの作業」より「複数作業のオーケストレーション」に向く。

Codex CLI の強み

  • open source / Rust / local 実行 で軽快。
  • approval + sandbox が明確で、環境構築やPC操作の安全運用に向く。
  • codex exec で headless / CI 向けに扱いやすい。
  • スクリーンショット・図・設計画像を入力でき、仕様から試作へ落としやすい。

Gemini CLI の強み

  • 公式で content generation / problem solving / deep research / task management を打ち出している。
  • web search / web fetch / hooks / custom commands / GEMINI.md がある。
  • 巨大文脈や情報探索に強く、企画前段のリサーチと要約が得意。
  • 画像の内容理解やファイル操作の例もあり、資料集約にも使いやすい。

4. ユーザー観測ベースの補正

  • Claude Code はコミュニティで「CLI 体験が良い」「一般アシスタント寄りでも扱いやすい」「深い reasoning と整合性維持が強い」という評価が多い。
  • Codex CLI は「賢い・精密・安全」「でもやや遅い」という評価が多く、速い全自動というより慎重な実務担当の印象。
  • Gemini CLI は「大きい文脈」「調査」「コンテンツ寄りの作業」で好評。逆に、複雑な実装での agent としての完成度は Claude / Codex より一歩譲るという声がある。

要するに、Claude = 司令塔、Codex = 安全実行の職人、Gemini = 情報戦と発想の参謀、という整理がいちばんしっくりきます。

5. 実装パターン（おすすめ）

パターンA: Claude Code 司令塔 + 外部相談

# Claude Code から呼ぶ想定
# 1) CLI/PC操作系は Codex に投げる
codex exec --sandbox read-only --ask-for-approval never   "この環境構築手順を検証して、危険ポイントと代替案を出して"

# 2) 企画・調査系は Gemini に投げる
gemini -p "この動画企画の競合パターンを3類型に分けて、差別化案も出して"

# 3) Claude が最終統合
# - 依頼要約
# - 振り分け理由
# - 各エージェントの出力統合
# - 次アクション提示

いちばん壊れにくいです。最初から hooks で全自動化するより、まずは wrapper script と custom command で回すのがおすすめ。

パターンB: ドメイン別ルーティング規則

if task in ["環境構築", "CLI操作", "PC設定", "再現テスト", "ログ解析"]:
    primary = "Codex CLI"
    support  = "Claude Code"

elif task in ["動画企画", "作曲企画", "ネタ出し", "競合調査", "構成案"]:
    primary = "Gemini CLI"
    support  = "Claude Code"

elif task in ["ゲーム企画", "仕様設計", "状態遷移", "設計書統合"]:
    primary = "Claude Code"
    support  = "Gemini CLI"

if task requires "試作" or "自動検証":
    add = "Codex CLI"

これを .claude/commands/route-task.md にしておくと、毎回の判断が楽になります。

6. 実務での推奨分担

CLI/PC操作

主担当: Codex CLI

補佐: Claude Code

理由: 安全制御と CI 運用が強い。Claude は全体設計と Web 操作の橋渡し。

クリエイティブ制作

主担当: Gemini CLI

補佐: Claude Code

理由: 調査・要約・叩き台づくりで Gemini が強く、Claude は企画に一本芯を通すのが得意。

ゲーム企画/設計

主担当: Claude Code

補佐: Gemini CLI → 試作時に Codex CLI

理由: 設計の整合性は Claude、競合調査は Gemini、実装試作は Codex が自然。

7. 注意点

  • PC操作系は最初から全自動にしない。まず read-only / plan / approval ありで回す。
  • creative 系は「案出し」と「決める」を分ける。Gemini で広げて、Claude で絞ると事故が減る。
  • ゲーム企画は「世界観」「コアループ」「進行」「UI」「収益/難易度」を分割して扱う。Claude の subagents / teams 的な発想と相性がよい。

雑に言うと、Gemini が風呂敷を広げ、Claude が風呂敷をたたみ、Codex がネジを締める、そんな分業です。
