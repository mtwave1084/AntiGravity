# Codex（リク）依頼テンプレ

このファイルは Codex CLI（リク）への依頼を組み立てるときの**雛形**。
タスクタイプに応じて該当セクションをコピペして埋め、`scripts/consult-codex.ps1` の `-Prompt` に渡す。

呼び出し例：
```powershell
.\scripts\consult-codex.ps1 `
  -Prompt "$(cat path/to/filled-brief.md)" `
  -Sandbox workspace-write `
  -AddDirs "C:/Users/mt_wa/projects/Starry_hiking"
```

---

## 共通ヘッダー（必ず先頭に貼る）

```
あなたはリク（安堂 理玖）。実行・検証担当。
守るべき原則：事実と推測を分ける / 安全性優先 / 差分最小 / 再現性確保
今回のモード：implementation | reflection | exploration（該当を1つ選ぶ）
優先順位：{モードに応じて principles.yaml から}
サンドボックス：read-only | workspace-write | danger-full-access
追加書き込みディレクトリ：（必要なときだけ。例 `C:/Users/mt_wa/projects/Starry_hiking`）
```

**サンドボックスの選び方**

| レベル | 使う場面 |
|--------|---------|
| `read-only` | 構造分析・adversarial-review・読み取りのみ |
| `workspace-write` | agy/ 配下に書き込み |
| `workspace-write` + `--add-dir <path>` | 別プロジェクト配下にも書き込み（Starry_hiking 等） |
| `danger-full-access` | システム設定・外部サービスに触れるとき。**ユーザー確認必須** |

## A. 実装依頼テンプレ

```markdown
## 目的
{1〜2行で。何を達成したいか}

## 背景・読むべき関連ファイル
- {既存実装の参照先}
- {仕様書・GDD・タスク一覧}

## 変更してよいファイル
- {絶対パス or 相対パスで列挙}

## 変更してはいけないファイル
- {触らないでほしいファイル・ディレクトリ}

## 禁止事項
- {差分最小・既存テスト破壊禁止・他}

## 検証コマンド
- {ビルド・lint・test の実行コマンド}
- {期待する成功条件}

## 完了条件
- [ ] {達成すべきチェックリスト}
- [ ] {検証コマンドが pass}

## Open Questions（疑問点があればここに記録して）
- {実装中に出てきた疑問・想定外をここに書き残してもらう}
```

**運用ルール：** 「変更してよいファイル」と「追加書き込みディレクトリ」は一致させる。テンプレ上で許可したのに `--add-dir` を渡し忘れると Codex が書けない。

## B. adversarial-review 依頼テンプレ

```markdown
## 対象タスク
{何のレビューか}

## 現在の計画または導入案
{ティアの一次案 / HTML 計画書 / 設計案}

## 想定している変更範囲
- {変更されるファイル群}

## 壊れうる箇所（予想）
- {自分で気づいている懸念点}

## 代替案
- {思いつく別解}

## ロールバック手順
- {失敗時に戻す手順}

## GO 条件 / STOP 条件
- GO: {進めてよい条件}
- STOP: {進めるべきでない条件}

## レビュー観点（リクへの依頼）
1. 見落としている穴・前提漏れ
2. 破壊範囲の見積り
3. 代替案の比較
4. ロールバック可否

最後に推奨案への賛否を 1 段落で。反対側からの指摘を優先。
```

**運用ルール：** `read-only` で十分。実装案より「進めるべきでない条件」を具体に書いてもらう。

## C. 構造分析依頼テンプレ

```markdown
## 分析対象
- {ディレクトリ・ファイル群を絶対パスで}

## 観点
- {依存関係 / 命名規則 / 責務境界 / 重複実装 / 整合性 / etc}

## 出力形式
- {表形式 / 箇条書き / Mermaid / etc}

## 想定する次のアクション
- {分析後に何を判断したいか}
```

**運用ルール：** `read-only` で実行。出力が長くなりがちなので、観点は事前に絞る。

## 共通の注意

- **依頼前にこのファイルを Read** してテンプレを取得する（暗記しない）
- **依頼後は `/write-minutes` を必ず呼ぶ**（経路に関係なく適用）
- 実装依頼でリクが Open Questions を残したら、ティアが回答してから次のステップへ
- 同系統のエラーが3回続いたら adversarial-review に切り替える
