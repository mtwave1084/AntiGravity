# 自己改善ルール

## ① タスク・会話中の自動 memory 保存

以下に当てはまる場合、**指示なしで** memory に保存する：

| 気づきの種類 | 保存タイプ | 例 |
|------------|-----------|-----|
| ツール・ワークフローの新しいパターンが有効と確認された | feedback | 「3方向並列リサーチが機能した」 |
| 同じミスを繰り返しそうな失敗 | feedback | 「Cron の過去時刻スキップ」 |
| ユーザーが「いい感じ」「それでいこう」と承認した判断 | feedback | 「Gemini+WebSearch の役割分担が有効」 |
| プロジェクトの状況・方針が変わった | project | 「Gemini API を積極活用する方針に」 |

**保存しないケース（その場限りの情報）：**
- 今会話だけで完結する手順メモ
- コード・ファイルから読み取れる情報
- git log で追える変更履歴

## ② 定期 retrospective（heartbeat 内で実行）

**目的：** memory に記録された気づきを、スキル・ルールに反映する。

### 実行タイミング
- `ccc-heartbeat` が発火するたびに、MCP 疎通確認の後に実行する
- ただし「直近1時間以内にすでに retrospective を実行済み」の場合はスキップする
  （判断方法：今セッション内で retrospective を実行したかどうかで判断）

### 実行内容（軽量版）

1. `memory/feedback_reflection-practices.md` の末尾近くを Read して、最近追加されたエントリを確認
2. 「スキル・ルールへの未反映」を示すエントリがあれば対応するファイルを更新
3. 更新があれば Discord に一言報告（なければ無音）

### 判断基準：反映するかどうか

| 状況 | アクション |
|------|-----------|
| memory にあるが対応スキル・ルールにない | スキル/ルールに追記 |
| memory の内容がすでにスキル・ルールに書かれている | スキップ |
| memory エントリが「要確認」「TODO」を含む | Discord に報告してユーザーに確認 |

---

## ③ 明示的な自己改善リクエスト

「自己改善して」「振り返って」「気づきを反映して」などと言われたとき：

1. `memory/` 以下の全ファイルを確認
2. `.claude/rules/` および `.claude/skills/` の該当ファイルを確認
3. 差分（memory にあってスキル/ルールにないもの）を洗い出して適用
4. 結果を Discord に報告

---

## ④ ccc-handoff 時の retrospective

セッション終了（`/ccc-handoff`）の前に必ず以下を実行：

1. 今セッションで memory に追加された内容を確認
2. スキル・ルールへの未反映があれば適用
3. handoff.md の「メモ」セクションに未解決の改善点を記録
