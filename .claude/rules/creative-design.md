# クリエイティブ設計ワークフロー

ゲーム・コンテンツ・キャラクター等の創作設計タスクに適用するルール。

## 反復的アイデア出しパターン

### フェーズ構成

```
Phase 1: 発散
  → Gemini に 20〜30 案を一度に出させる
  → テーマ・制約を与えるが絞り込みはしない
  → 複数ラウンド可（テーマを変えて再発散）

Phase 2: 絞り込み（ユーザーが行う）
  → Claude/Gemini は候補を提示するが、最終選択はユーザー
  → 「気になる」「好き」「面白い」などの反応を見て絞る

Phase 3: 詳細化
  → 選んだ案についてジャンル・操作・クリア条件を具体化
  → ユリ（Gemini）主導、ティア（Claude）が確認・補足

Phase 4: 深掘り設計
  → コアメカニクス・感情の流れ・エリア構成などを詳細設計
  → ティアとユリで対話しながら固める

Phase 5: 仕様化
  → 複数セッションの成果を統合した文書（GDD・仕様書）を生成
  → `Contents/{テーマ}-gdd.md` に保存
```

### 各フェーズのルール

- **発散時**: 量を出すことを優先する。クオリティより発想の多様性
- **絞り込み**: ユーザーの感覚・好みを最優先する。「なんかいいな」が正解
- **深掘り**: 「急かさない・スタミナなし」等の体験設計の原則は早めに確認する
- **仕様化**: 未確定事項は「確認・検討事項」として明示し、決定済みと混在させない

## 画像レビュー（コンセプトアート確認）

生成されたコンセプトアートをGeminiでレビューする場合：

```
1. Discord attachment を download_attachment でダウンロード
2. assets/ にコピー（例：assets/starry_hiking00.png）
3. gemini --yolo -m gemini-3.5-flash -p "@assets/filename.png ..." でレビュー
4. 設計文書との一致・相違・要確認点をまとめて Discord に返信
```

**レビューの観点:**
- コアメカニクスがビジュアルで表現されているか
- エリア構成・世界観が設計意図と一致しているか
- UI/HUDが体験設計の方針と矛盾しないか（急かす要素がないかなど）
- 固有名詞・設定の正確さ（星座名・地名など）

## 仕様書（GDD）のテンプレート

```markdown
# {タイトル} — ゲームデザイン文書

## 概要
| 項目 | 内容 |
（タイトル・ジャンル・プレイ時間・プラットフォーム・コンセプト）

## コアコンセプト
（キャッチコピー・体験の本質を1〜2段落で）

## コアメカニクス
（操作・ゲームシステムの仕組み・補助機能）

## ゲームの進行
（エリア構成・クライマックス）

## 体験設計
（感情の流れ・テンポの方針）

## UI・情報設計

## 確認・検討事項
```

## 注意

- ゲーム設計の各フェーズ完了後に必ず write-minutes を実行する
- 仕様書の「確認・検討事項」は次回セッションへの引き継ぎとして機能する
- プラットフォーム・エンジンの選定は仕様が固まった後に行う（先に決めない）
