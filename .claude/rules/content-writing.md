# Brain記事執筆ルール

## スタイルの基本原則
- 参照記事: `Contents/Brain参考記事/ユニコ記事`
- プラットフォーム: Brain（https://brain-market.com）向けセールス記事
- ターゲット: AIエージェント・動画制作・Claude Code に関心のある日本語話者

## 構成パターン
```
タイトル（絵文字入り・インパクト重視）
↓
目次（番号付き、1-1〜1-N のサブセクション構造）
↓
1. メインセクション（問題提起＋解決策＋実績）
  1-1. 読者の悩みを言語化
  1-2. 著者の自己紹介・実績
  1-3〜1-N. 機能・特徴・特典の詳細
  1-N. FAQ
↓
2. 価格（🟢🟡🔴 段階値上げ＋購入CTA）
```

## トーン・文体
- **熱量**: 「！！」多用、太字での強調を積極的に使う
- **共感**: 読者の痛みを「〜ではないでしょうか」で言語化してから解決策を提示
- **転換**: 「だけど違います」「でも安心してください」「もう必要ありません」
- **具体性**: フォロワー数・インプ数・受講生数などの実績数字を入れる
- **CTA**: 各セクションの末尾で軽く行動を促し、最後の価格セクションで強くCTAを入れる

## 構成案の先出しルール

- 台本・記事など3パート以上の長いコンテンツを生成する前に、構成案（パート分け・尺・トーン）を Discord に出して「この方向でいい？」と確認してから本文を書く
- 理由：尺・ターゲット・トーンが合っていないとまるごと書き直しになる。最初に合意するほうが摩擦が小さい

## 情報鮮度チェックルール

- リサーチを含むコンテンツ（動画台本・記事等）は情報の鮮度を確認してから書く
- 1年以上前の事例・数字は差し替えるか、Geminiで最新情報を取得してから使う
- 「2025年はAIエージェント元年」のような時事フレーズは年次が古くなるので要注意
- Gemini の数字やURLはハルシネーションを含む場合があるため、具体的な数字には「一次ソース確認推奨」の注記を入れる

## 成果物の納品ルール

- 台本・記事など md ファイルを生成したとき、HTMLレポートとあわせて **md も Discord に添付する**
  - HTML はレポートUI、md が実際の編集可能な本文。両方ないとモバイルから本文が確認できない
- 古い情報と新しいが未検証な情報が衝突したら「どちらにする？」と聞かず、**第三の（新しくて確実な）事例を探しに行く**
  - 採用した事例だけでなく、不採用にした事例と理由も Discord に添える

## 禁止事項
- 過度に技術的・説明的な文体（セールス感を損なう）
- 箇条書きだけで構成された無機質なセクション（体験談・語りかけを混ぜる）
- 価格・日程の無断確定（仮値で書き、ユーザーに確認する）

## ファイル命名規則
`Contents/{記事トピック}_記事.md`
例: `Contents/AntiGravity_Remotion_記事.md`
